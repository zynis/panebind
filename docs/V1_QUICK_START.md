# PaneBind V1 候选版中文快速入门

这是开发候选的操作说明，整版验收尚未完成。源码版本、Release EXE 与文件哈希以随包 `manifest.json` 为准；实际通过、失败及未运行项目见[验收表](reports/V1_ACCEPTANCE.json)与[交付报告](reports/V1_DELIVERY_REPORT.md)。本文描述当前产品接线，不把设置、应用兼容或显示器矩阵的未运行项算作通过。

当前复核操作限已授权的可丢弃测试 guest，不构成普通宿主试用授权；自动 driver 不是日常使用的必要入口，也不是真人 UAT。

## 1. 正常便携启动与停止

将 Release 便携包完整解压到可写的新目录，保留 `panebind.exe`、`portable.flag`、许可证及说明文件。以当前登录用户的普通权限双击 `panebind.exe`；不要选择“以管理员身份运行”。正式产品要求 Medium/non-elevated，同用户、同交互 session，不控制 High、System 或安全桌面；旧 High guest 例外不适用于此入口。

当前候选首次普通启动显示中文设置；关闭或取消设置后，增强仍由同一后台实例／托盘管理。程序不创建控制台，也不要求三目录、RunId、输入 HWND 或逐窗确认。再次双击同一程序会请求打开已有实例的设置，不启动第二套增强。查看任务栏隐藏图标区可寻找 PaneBind；当前 guest 托盘图标可达性尚未通过，若找不到可使用下面的 `--settings`、`--pause`、`--quit` 请求，不把命令替代记作托盘验收。不要同时运行多个目录中的不同版本。

右击托盘可打开“暂停增强／恢复增强”“设置”“排除上一个应用”“窗口操作”“帮助”“导出诊断”和“退出”；单击或双击托盘图标也可打开设置。

- `Ctrl+Shift+F11`：紧急暂停，撤销当前增强手势；从托盘恢复后重新起手。
- `Esc`：取消当前增强手势；仅在身份与上下文仍有效时尝试恢复本次起点。
- 正常退出：托盘“退出”。不要用强杀进程代替正常清理。

已有实例运行时，也可从包目录请求控制：

```powershell
.\panebind.exe --settings
.\panebind.exe --status
.\panebind.exe --pause
.\panebind.exe --quit
```

这些命令分别请求设置、记录状态、暂停和退出；命令发送成功不等于所有清理已完成。`--status` 写入本地日志，不弹状态控制台。窗口命令前先切到目标应用；产品重新核验最近有效目标，不把托盘／设置本身当作被操作窗口。

## 2. 移动、联动、停靠与拉伸

- 普通移动：在有效标题栏按住左键拖动。接近合格窗口或工作区边缘时磁吸，继续拉开可脱离，再靠近可重吸。默认吸引 10 DIP、释放 16 DIP、快移抑制 2000 DIP/秒。
- Ctrl 联动：在按下前按住 `Ctrl`，按实际邻接关系冻结本次组。任意成员可发起；角点相碰不算邻接，没有永久 Leader 或永久绑定。共享边／角上的 Ctrl Resize 调整受影响成员，仍受各应用尺寸约束。
- 临时原生操作：普通拖动起手前按住 `Shift`，绕过增强；`Ctrl+Shift` 起手同样优先绕过。中途松按修饰键不重选本次模式。明确配置的 Shift 双击动作不受此规则取消。
- 普通 Resize：拖动边或角；启用磁吸时仅修正活动边，应用最小／最大尺寸或自定义栅格可能限制结果。
- 停靠：普通 Move 到屏幕边角显示预览，移开取消，正常松键提交。默认左／右半屏、顶部最大化、底部下半屏、四角四分屏；“上半屏”可在设置中另选。显示器接缝有停留时间，避免把跨屏移动当成停靠。
- 拉伸：双击边向该方向拉伸，Shift 双击边沿同轴双向拉伸，双击角沿两活动方向拉伸。智能模式使用最近且有正交交叠的合格邻窗，否则使用工作区边缘；不会挪动别的窗口挤空间。

标题栏左键双击默认最大化。已经停靠的窗口可拖离恢复；最大化起手走实际恢复后继续移动的候选路径。恢复／撤销布局只使用本窗口仍有效的有限记录；手动改变或窗口重建后不会强套旧位置。这些行为已接线，是否在某应用、DPI 或打包版本中通过，仍以该构建的实际验收为准。

## 3. 默认快捷键

Windows 自有 `Win+方向键` 保持原有映射；以下为 PaneBind 默认值，修改后以当前设置为准。

| 快捷键 | 动作 |
| --- | --- |
| Ctrl+Alt+左／右 | 左／右半屏 |
| Ctrl+Alt+上／下 | 最大化／下半屏 |
| Ctrl+Alt+C | 居中 |
| Ctrl+Alt+R | 恢复 |
| Ctrl+Alt+U | 撤销布局 |
| Ctrl+Alt+T | 切换置顶 |
| Ctrl+Alt+N | 移到下一显示器 |
| Ctrl+Shift+F11 | 紧急暂停，保留键 |

托盘“窗口操作”还提供最小化、置后、按步长微移／调宽高、提高／降低不透明度、各方向停靠和拉伸。置顶与透明度分开记录；清理只恢复 PaneBind 仍拥有的改变，不覆盖应用后续自行改变的属性。拖动透明和摇动默认关闭，可在“诊断／外观”启用；发生原生调用超时或恢复未确认时，不要把界面返回当作已恢复完成。

## 4. 六页设置与键盘操作

| 页面 | 主要选项 |
| --- | --- |
| 常规 | 启用、用户登录后启动、设置窗口淡入 |
| 磁吸／联动 | Move／Resize 磁吸、Ctrl 联动、吸引／释放／速度／邻接参数 |
| 停靠／拉伸 | 八方向动作、智能停靠／拉伸、预览颜色／透明度、接缝停留 |
| 快捷键／鼠标 | 微移步长、键盘映射、九区五键鼠标映射及动作说明 |
| 应用规则 | 从前台应用添加排除、可选类名限制、规则文本 |
| 诊断／外观 | 关系提示、拖动透明、摇动参数、配置版本／代际与诊断 |

`Tab`／`Shift+Tab` 切换控件，`Ctrl+Tab`／`Ctrl+Shift+Tab` 切换页面；页签获得焦点时可用方向键。小窗口或高 DPI 下可滚动页面；键盘焦点会使对应控件可见。在保存按钮上按 `Enter` 保存，在设置中按 `Esc` 取消；多行编辑框里的 `Enter` 用于换行，不要把它当保存。

所有修改先留在草稿：“保存并关闭”成功才应用；“取消”或关闭窗口不提交。“此页默认／全部默认”也只改草稿。释放距离必须严格大于吸引距离；非法数值、重复映射或真实热键注册冲突会拒绝保存，保留原有效配置。

“导出…”将当前经过校验的草稿写为 `.conf`，不会应用该草稿；“导入…”读取到草稿，检查后仍需保存，取消则运行配置不变。导入文件必须是完整 PaneBind 配置，而非下面的局部示例。登录启动默认关闭；仅在获准环境中明确勾选并保存后创建自己的用户级入口，取消勾选并保存后移除自己的入口，不覆盖未知的同名启动项。

### 键鼠映射与最小规则示例

键盘格式为 `hotkey.编号=修饰键,十进制虚拟键码,动作标识`；鼠标格式为 `mouse.编号=区域,按键,点击次数,修饰键,动作标识`。修饰键 Alt=1、Ctrl=2、Shift=4、Win=8，可相加；F12 和紧急暂停组合不可用作自定义热键。鼠标标题区=0，左／右／上／下=1–4，左上／右上／左下／右下=5–8；左／右／中／X1／X2=1–5，单击=1、双击=2。未映射的普通按钮和客户区输入透传。

列表必须连续从 0 编号，并同步更新相应 `hotkey_count`、`mouse_count` 或 `rule_count`。删除映射后同样重新编号；“此页默认”可恢复默认键鼠列表。

规则按实际 exe 名称或完整路径，以及可选的精确类名匹配，不读标题、不支持通配符。先切换到目标应用，再打开设置，点“添加已核验前台应用的排除规则”；勾选类名限制可只排除这一类窗口，保存才生效。取消排除时删除对应行、调整计数和编号后保存。

仅有一条规则时，下面片段表示排除所有 `notepad.exe` 窗口：

```text
rule_count=1
rule.0=notepad.exe||true|4294967295
```

仅有该规则时，可改为 `rule_count=0` 并删除 `rule.0` 取消排除；已有其他规则时不要直接覆盖它们。路径中的空格、`%`、`|`、`=`、`#` 需按 UTF-8 字节写为 `%HH`（例如空格 `%20`）。最后一列 `4294967295` 为全部功能位；`true` 表示排除。

## 5. 文件、诊断与验收边界

保留 EXE 同目录 `portable.flag`，配置使用同目录 `settings.ini`；没有该标记时使用当前用户 `%LOCALAPPDATA%\PaneBind\settings.ini`。这是 UTF-8 严格行式配置，不是任意 INI／JSON。损坏配置会先留存为 `settings.ini.corrupt.<时间>`，再使用默认值；无法备份时不静默覆盖原文件。正常运行时不要同时用外部编辑器覆盖配置。

配置目录中的 `panebind.log.jsonl` 有限轮转。“导出诊断”在同目录生成诊断文本，包含构建、OS／DPI、必要窗口类别、脱敏设置和最近终止原因，不采集文档内容或键盘文本。更换包前保留 manifest、日志和失败证据；回报问题时注明窗口应用、操作顺序和实际包身份。

整版 Release／Medium、应用兼容、真实多屏／混合 DPI、连续运行与真人手感分别验收，不由本文或构建成功推定通过。`source_commit` 表示二进制 RUNTIME，`packaging_head` 表示文档打包提交；两者不同仅允许三份交付文档的已提交差异，并保留文件哈希，不把文档提交冒充已测二进制。旧 High guest 局部结果不能替代正式普通权限验收；未运行项目继续为 `NOT_RUN`，真人 UAT 为 `PENDING`。不要在重要未保存工作或未获准的宿主桌面上试验候选版。

# PaneBind V1 完整开发与 DEV 验收指导方案

版本：1.0 · 日期：2026-10-15 · 状态：已获用户范围授权，待连续开发执行。

这是本版本的唯一主执行方案。开发顺序是：建立产品主线 → 连续实现全部模块 → 集成自测与修复 → 整版交付 → 用户集中 review → 集中修订。内部里程碑不构成再次申请授权的边界。

**交付目标：Windows 11 x64 普通权限下可实际使用的便携窗口管理工具；完成本方案固定的 40 项 AquaSnap 对标能力中的 32 项，达到本合同 80% 功能覆盖，超过用户要求的 75% 下限。** 32 项全部属于本轮必做范围，不能完成 30 项便自行停止。还须同时通过产品可用性、连续操作、兼容性及退出门槛。

这不是对未来实现结果的预先保证，也不是对 AquaSnap 整个产品成熟度的客观百分比。百分比仅指第 3 节公开、固定、等权的功能检查表；性能、手感、兼容性、缺陷和真人 UAT 单独报告。任何缺项不得通过修改分母、拆分简单功能、删除失败用例或抬高外围功能权重消除。

## 2. 持续授权、旧规则替代与执行边界

### 2.1 本次用户决定

用户已确认 12 模块的完整首版范围，并允许重新评估不注入进程的低级鼠标钩子等事件机制；同时要求宽松、连续的开发授权，整版开发结束至少达到 AquaSnap 75% 的功能目标。

本轮授权包含以下必要工作，Codex 自行决定次序并持续执行，不逐项回问：

1. 实现 M01–M12 的全部 60 个功能点，接入真实生产入口；完成相应重构、缺陷修复、UI、配置、文档和便携包。
2. 比较、选择、实现和替换本进程中的事件/输入方案，包括 `WH_MOUSE_LL`、out-of-context WinEvent、Raw Input 的合理组合；不要求保留旧 cancellation/AttachThreadInput/capture/shield 架构。
3. 用符合既有工具权限的方式构建 Debug/Release、运行离线和隔离现场 DEV、诊断、修改并复验。Debug 的局部失败不自动禁止 Release 诊断。
4. 在本任务专属可丢弃隔离环境中准备 DEV 窗口、临时目录、测试配置和普通权限会话；使用已安装的隔离基础设施建立必要的 Medium 测试环境。测试范围可以是多种应用及多于三个窗口，无须重新批准每个 fixture。自动驱动始终如实标记，不称作真人同意或真人 UAT。
5. 在开发分支标准 commit/push，保存有用证据、交付候选包和集中缺陷清单。常规接口选择、配置默认值、测试驱动适配、范围内架构替换和有证据的诊断均不再单独申请。
6. 对已验证兼容的宽松许可依赖，由 Codex 完成来源、许可和归属核对后自行作出小范围复用决定；GPL 代码仍只作行为/思路参考，不复制、翻译或改编成 MIT 代码。

## 4. 软件结构、共享合同与默认交互

### 4.1 12 个逻辑模块

| 模块 | 职责 | 主要依赖 | 建议实现位置（可按现有结构调整） |
| --- | --- | --- | --- |
| M01 | 应用生命期、托盘、启停 | M04、M11 | `src/app/` |
| M02 | 窗口资格、生命周期、显示器 | Windows adapter | `src/platform/windows/window_catalog/` |
| M03 | 几何与窗口操作、约束/回读 | M02、现有 geometry/operations | `src/core/`、Windows operations |
| M04 | 输入、手势、行为仲裁、异常收尾 | M02、M03 | core behavior + Windows input adapter |
| M05 | 磁吸 | M02–M04 | core magnet + adapter 接线 |
| M06 | 关系图和联动移动 | M02–M05 | core topology/behavior |
| M07 | 联动缩放 | M02–M04、M06 | core resize + adapter 接线 |
| M08 | 停靠、拉伸和恢复 | M02–M04 | core docking/stretch |
| M09 | 键鼠命令、置顶/透明/摇动 | M02–M04、M08 | app commands + Windows adapter |
| M10 | 预览和关系反馈 | M04–M09 | Windows overlay/UI |
| M11 | 设置、应用规则、配置版本 | M01、各模块参数 | app settings + native UI |
| M12 | 日志、证据、打包、帮助 | 全部 | app diagnostics / scripts / docs |

逻辑模块不等于独立进程、插件或 DLL。不建立插件平台、远程控制框架、通用权限 DSL 或未来跨平台空壳。

### 4.2 唯一生产数据通路

原生事件 → 轻量输入适配 → 已验证窗口快照/标准事件 → 单一手势调度器 → 纯几何计划 → Windows writer → 实际结果回读 → 关系刷新/反馈。

键盘、鼠标、托盘和测试控制入口调用同一命令服务。所有测试不得另写一个功能更完整、保护更宽松的“测试产品”。测试接口只提供输入和观测，不能替代用户路径。

必要的最小数据合同如下，名字可改，语义不能缺：

| 合同 | 必含字段和保证 |
| --- | --- |
| WindowIdentity | 不透明 ID、native 身份关联、PID/出生或等价身份依据、HWND 代际；复用句柄不能继承授权 |
| WindowSnapshot | visible/frame rect、positioning rect、状态、min/max 能力、display/DPI、规则结果、采样代际 |
| DisplaySnapshot | signed physical-pixel 工作区、DPI、拓扑代际；允许负坐标和非矩形联合桌面 |
| GestureContext | gesture ID、类型、source、起点鼠标/几何、锁定修饰键、参与成员及规则/拓扑版本 |
| OperationPlan | 起点快照、绝对目标矩形、活动边、参与成员、理由、预期状态；不累加已修正矩形造成漂移 |
| OperationReceipt | 真实 API 结果、实际回读矩形、时间/序列、成功/应用钳制/失效/部分完成；不伪造事务成功 |
| AppCommand | 类型、目标选择、参数、来源；统一结果码和中文可理解失败说明 |
| SettingsSnapshot | schema 版本及配置代际；当前手势使用固定快照，下次手势采用新配置 |

### 4.3 通用几何规则

- 核心统一使用有符号 64 位物理屏幕像素，矩形半开区间 `[left, top, right, bottom)`。Win32 类型仅在 adapter；DIP 参数在入口按目标 DPI 转换一次。
- visible bounds 与 positioning bounds 必须分开；DWM 阴影不参与邻接。DPI/主题改变后重新测量边框，不使用陈旧偏移。Resize、跨屏和最大化后的转换须有实际回读证据。
- 浮点比例仅用于计算理想分割线，提交前确定性整数化：中线向下取整，右/下区域承接余数，共享边使用同一数值，不能各自四舍五入出缝。
- 联动成员冻结于手势起点，结束后从实际几何重建；无永久 Leader，无跨手势永久绑定，关系不授予窗口控制权。角点相碰不算正长度邻接。
- writer 预检所有成员后才提交批次；Win32 批处理不是数据库事务。部分失败时停止该手势并回读，不能无限重试或移动未知对象补偿。
- 对系统真实最小/最大尺寸和应用自定义钳制做区分。不得假定从另一进程简单发送 `WM_GETMINMAXINFO` 就能得到完整原生约束；先用文档和 fixture 验证采用的通路。无法精确得知时保守计划、核验实际结果并记录限制，不能给出重叠/负尺寸。
- 用户 Esc 取消的常规路径可恢复本次仍有效窗口的起点矩形；若权限/身份已失效则仅停止，不能为了“恢复”继续越权。结束不复原用户正常完成的排列。

### 4.4 默认值与行为优先级（PaneBind 自定）

默认启用：移动/缩放磁吸、Ctrl 联动、停靠、拉伸、预览；摇动/拖动透明可在设置中启用，必须可发现且实际测试，不能以默认关闭逃避实现。登录启动默认关闭，不在开发宿主上自动启用。

| 项目 | 初始默认合同 |
| --- | --- |
| 磁吸 | 吸引距离 10 DIP，释放距离 16 DIP；换算后按物理像素计算。速度阈值初始 2000 DIP/s，可配置；只做有限调参 |
| 邻接 | 边缘容差初始 2 DIP，须正长度交叠；与磁吸距离分开。瞬时源窗口自身写入回执不重复触发关系传播 |
| Ctrl | 在有效 DOWN/手势开始锁定为组移动或组缩放，中途松按不改变模式 |
| Shift | 手势开始时 Shift+Move 临时禁用磁吸/停靠/联动；Shift+边角双击用于双向拉伸。Ctrl+Shift+Move 以临时禁用优先 |
| 停靠 | 左/右半屏，角四分屏，顶部最大化，底部下半屏；设置可改为四方向半屏。屏幕接缝须有明确停留意图再触发，不阻塞跨屏 |
| 热键 | 默认保留 Windows 原 Win+方向键；PaneBind 使用可配置的 Ctrl+Alt 组合。冲突不得静默抢占 |
| 停止 | Ctrl+Shift+F11 为紧急暂停/撤销当前手势；托盘退出为正常退出。注册冲突明确显示，保留托盘和有界 stop 入口 |
| 优先级 | 停止/失效 > 暂停/排除 > 明确快捷命令 > Ctrl 联动 > 停靠预览/提交 > 普通磁吸 > 原生行为 |

组移动不在手势中途突然升级为组停靠；组 Resize 不启动独立窗口停靠。停靠预览出现时压过屏幕磁吸，离开触发区即撤销预览，松键才提交。托盘/设置窗口打开时不把该 UI 当作被操作目标；命令应捕获最后一个有效前台应用目标。

## 5. 输入路线选择：允许更换，不再无限追查旧路径

### 5.1 有限路线选择

默认优先调查：在合格标题栏/边框的真实 DOWN 时识别手势，用非注入 `WH_MOUSE_LL` 支持轻量输入识别/必要抑制，工作线程执行几何，WinEvent 负责窗口生命周期；这样有机会避免进入原生 modal loop 后再 cancel/Attach/capture/shield 的多次交接。**这是候选工程判断，不是已经验证的成功架构。** 原生行为、鼠标按键、捕获、焦点、双击及应用差异必须现场验证。

沿用旧接管路径也可以，但必须能满足整版门槛，不能仅因为已有代码多就锁死路线。允许统一或拆分 Move 与 Resize 的适配方式，但对外状态/命令合同一致。单纯松手后再对齐不能替代实时磁吸或实时联动计分。

先完成最小产品外壳和独立可用的停靠/快捷命令，再用少量现场案例决定输入路线。最多比较两个实质不同候选，每个候选围绕当前假设最多三项有区分度的实验；无新证据不重复同一失败批次。数量是诊断纪律，不是失败后自动宣布成功或停止全项目的理由。

路线检查必须包含：普通窗口 Move → UP → Resize → UP → 再 Move，以及 Ctrl 组操作、Esc/失焦与下一次手势；至少一个真实非 Explorer 应用、Medium 和 Release。不要只测初次 A Move。若环境仅 High，可先做实现/预检并准备 Medium 路线，不能把环境缺口记成权限不足或功能 PASS。

### 5.2 回调和资源合同

- `WH_MOUSE_LL` 不注入其他进程，但需要安装线程消息循环，超时可能被静默移除。回调只读已准备的快照、做常数级判断并投递；不得在其中同步 COM、磁盘日志、枚举全桌面或等待跨进程消息。`nCode<0` 和未处理事件正常传递。
- 吞下某次 DOWN 必须有完整匹配的运动/UP/取消合同，不能吞下无关点击；菜单、按钮、滚轮、客户区、被排除应用默认透传。不能通过吞掉所有全局输入来取得控制。
- 快照不足以安全判定时允许该次原生交互，不抢回前台、不反复抢 capture。对预备快照如何及时更新做实测，不能盲等下次点击或用固定轮询替代。
- 保留单一手势所有者、写入代际与终止标志；撤权后新 writer 请求为零，旧队列丢弃。UP、Esc、失焦、窗口销毁、暂停、会话锁定均为明确终止原因；异常终止不得标 NormalUp。
- Windows 没有可靠查询“低级钩子是否被静默移除”的通用接口。不得实现虚假的精确健康探测；通过有界响应检查、可见异常状态及用户暂停/恢复重建路径处理，并测试注入的回调停止/队列故障。
- 不要求生产实现同时采用 Raw、legacy UP、capture 和 shield；要求选定路线真实满足输入不残留、写入不越界和可恢复。旧测试可以留在历史路径。

### 5.3 研究复用

优先阅读已有 [AltSnap review](research/ALTSNAP_REVIEW.md)、[FancyZones review](research/FANCYZONES_REVIEW.md)、[来源登记](research/SOURCE_PROVENANCE.md) 及相关修复史。复用已核验结论，只为新增/改变的具体机制补读上游、修复史和官方 API；每模块不要重做整份考古报告。

把“事实、候选推断、决定、现场结果”分开。查阅不到某项参考资料时只阻断依赖该资料的代码复用或假设；可继续独立原创且证据足够的模块。若必需资料仍缺，集中记录真实缺口，不把研究手续变成全项目停止器。

## 7. 自底向上的 DEV 验收

### 7.1 证据层级与状态

| 层级 | 要证明什么 | 不能替代它的证据 |
| --- | --- | --- |
| L1 功能/纯核心 | 固定输入的独立预期值、状态转换和约束不变量 | 只调用函数不核对结果；用被测求解器生成预期 |
| L2 模块/adapter | 原生 fixture 与真实接口的完整生产通路、异常路径、回读 | mock API 成功、私有 test-only 实现、仅检查日志字符串 |
| L3 跨模块 | 连续用户操作、行为仲裁、状态/资源不串台 | 重启产品后各测一个孤立功能 |
| L4 整版 Release | 正式入口、普通权限、应用/DPI 矩阵、打包及可用性 | Debug/High guest/源码目录运行、构建或测试数量 |
| L5 人工整体 review/UAT | 真实手感、易理解程度、长期使用发现 | 自动轨迹、截图、Codex 自称满意 |

每功能分别记录 `implementation = NOT_STARTED / IN_PROGRESS / IMPLEMENTED`、`dev = NOT_RUN / PASS / FAIL / BLOCKED`、`human = NOT_RUN / PASS / FAIL / N_A`。`IMPLEMENTED` 不等于 `PASS`；环境缺失是 `BLOCKED`，不等于逻辑失败，也不加分。人工审阅后按同一构建记录 UAT，不回填成早先已通过。

一次有意义的功能测试至少覆盖正常行为、真正相关的边界/冲突/失效，不机械要求每个 UI 文案都写单元测试。配置/窗口/输入的实际风险才决定负例数量。下面的确定数值和跨模块用例是必需基线，允许补充具体新风险，不增设无关测试批次。

### 7.2 独立几何与状态基准 G0–G11

所有数值都是本方案独立定义的 fixture 预期。纯计算必须精确相等；原生真实窗口按 actual visible bounds 核对。约束和 DPI fixture 的预期在测试前确定，不从产品输出反算。

**G0：真实窗口判定规则。** 标准 fixture 目标可表示时要求精确，DWM/应用在已说明的 DPI 换算处允许每边最多 1 物理像素舍入差，并额外核对共享缝总误差不超过 1 像素。应用尺寸栅格的不同结果必须显式标记 `APP_CONSTRAINED` 并验证预先定义的合法集合，不能随意放宽容差。原生拖动抢回位置、数十像素回弹、持续抖动不是舍入差。记录动作中及终止后位置；不能只看最终一帧而遗漏活动期失效。

| --- | --- | --- |
| G01 frame 转换 | visible `[100,100,600,500)`，positioning `[92,100,608,508)`；目标 visible `[180,130,730,570)` | 目标 positioning `[172,130,738,578)`；非对称边框保留。再覆盖负坐标和溢出拒绝 |

### 7.7 有限非功能验收

这些是首版预算，不是宣称已达到，也不代表必须做到旧长期目标 20 MB 才能交付：

- 在已记录的测试机器/VM，Release 正常空闲观测 60 秒，CPU 折合一个逻辑核平均低于 1%，无常驻短周期轮询；工作集目标不超过 80 MiB。报告真实值及设置，不跨机器作性能结论。
- 如采用低级 hook，记录回调耗时分布，正常路径目标 p99 < 1 ms；禁止阻塞 API 和磁盘 IO。输入到写入回读 p95 目标 < 50 ms，超过 100 ms 的持续停顿需要作为体验缺陷调查；消息时间不能冒充物理显示延迟。
- 预热后完成 I11，退出无残留进程/浮层/钩子；句柄和 GDI/USER 对象不单调无界增加。记录前后计数，允许有解释的有限缓存，不为追求某个整齐数字反复重构。
- 无 S0：数据丢失、越界操作、长期输入封锁。无 S1：必做能力失败、常见操作频繁终止、需频繁重启、矩阵核心应用不可用或无法可靠退出。
- S2：可绕过的视觉/文案/较少见非核心兼容问题。S2 不能用于降低必做功能或硬门槛；列入集中修改清单。

达到上述门槛后停止无关性能打磨和追加稳定性批次。最终只对存在具体证据的缺陷扩大检查范围。

### 7.8 证据记录格式

保留一份机器可读验收表及一份整版报告，开发结束时生成，不现在制造空 PASS。建议路径：

- `docs/reports/V1_ACCEPTANCE.json`：60 功能、12 模块、B01–B40、I01–I12、环境矩阵和汇总。
- `docs/reports/V1_DELIVERY_REPORT.md`：面向用户的交付、限制、证据索引、集中缺陷。

六阶段不是六次聊天审批。中间给简短进展可以，但不得用阶段性最终回复主动结束任务、要求“是否继续”。遇到上下文压缩使用精简检查点继续；工具/时间/配额实际中断时保存状态和准确恢复动作，不能承诺任何平台一定允许无限持续运行。

### 8.2 依赖与可继续工作

- M02/M03/M04 是实时行为公共基础，但不是 UI、配置、包结构、快捷命令纯模型的共同阻断器。
- M06 的邻接关系是 M07 的输入；M07 不需要等 M05 每一处手感调好才开始。M08 的离散动作可以先于实时磁吸完成。
- M11 的数据结构和最小 UI 在 P1 建立，P3 补齐；不是最后才接配置。M12 的构建身份/最小日志从 P1 起存在，P5 才生成完整交付材料。
- 最晚在 P2 验证真实通用应用，不能在 60 个功能全部写完后才发现接入只支持 Explorer。

### 8.3 排障预算和降级规则

每个局部阻断记录：现象、直接影响的 IDs、当前证据、下一个可区分假设、已尝试方法及结果。最多三次无实质新证据的同路线尝试后必须停止重复，选择另一条已授权路线或转向未阻断的功能；不能再堆一个隐藏窗口/日志框架当作主线进展。

允许的开发期降级：某可选视觉效果临时关掉用于定位、单屏先集成、多屏环境稍后补、旧路保留供对照。**交付期不能用降级消除必做项**：实时磁吸不能变成松手纠正，组 Resize 不能变成仅刷新关系，普通产品不能变成三个 Explorer driver，Medium 不能变成 High。

如果某必做项在本轮实际资源内仍无法实现/验证，完成全部不受影响工作后交付诚实的 `PARTIAL / ENVIRONMENT_BLOCKED` 候选，集中给出剩余工作；不得写成完成 80%，也不得只留一份新的诊断建议。继续开发至门槛是目标，不能用文档保证替代技术事实。

### 8.4 如何衡量进度

进度只报四个量：生产接通的功能数 `/60`、当前 DEV PASS 数 `/60`、对标 PASS 数 `/40`、通过的整链/环境项。另附最影响交付的 1–3 个缺陷。测试条数、代码行、提交数不作为产品完成度。

不沿用未经工作分解的“3–6个月”估算，也不虚构一次对话必定完成的时长承诺。P1 后可以用实际完成速度更新剩余工作量，但不能因此缩小已冻结范围。优先减少反复授权、重复研究、无效排障和迟到集成，而不是跳过必要验收。

## 9. 最终交付与集中 review

### 9.1 开发结束必须提供

1. 当前 Release 便携包，主程序和中文快速入门；正常用户入口已由实际包验证。
2. 源码和工作分支、起止 SHA、构建源码 SHA、包/主要二进制 SHA256、构建命令、标准 Git 推送与远端核对结果。
3. 60 功能、12 模块、40 对标项和整链/环境矩阵的真实结果，证据按 ID 可定位。
4. 一份集中缺陷清单：严重度、影响范围、复现、证据、原因确定度、建议修复；避免几十份互相覆盖报告。
5. 明确说明用户现在能启动什么、操作什么，已知限制和退出方法；测试数字作为附录。

`COMPLETE` 要求 B01–B32、全部功能/模块及适用硬门槛通过。任一必需真实环境缺失则不能用 `COMPLETE`；实现完整和验收完整分别陈述。不为了凑 75% 而挑 30 个最容易用例。

### 9.2 用户 review 的范围

用户在整版候选上集中检查：拖动/缩放手感，行为是否可预测，常用工作流，中文 UI，可发现性，误触，性能和日常兼容。把所有修改项归并到同一清单，随后一次集中修改。DEV 期间已经找到的功能缺陷由 Codex 自行修复，不积攒给用户当测试员。

集中修订沿用本方案不变范围及验收口径，按影响重验；新增需求单独列候选，不自动混入当前版本。达到交付门槛后不主动开启新大轮优化。
